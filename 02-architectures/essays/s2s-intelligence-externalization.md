## 0. 结论先行

**要求确实高，而且 S2S 在"智力"上确实弱于同代文本模型。** 但这不等于 S2S 不能用：成熟架构的共同答案是 **S2S 负责在场和表现力（快、语气、副语言、人设声音），智力放在别处（规则、工具层、后台文本模型、自己的数据）**。本文的六个手段就是把"智力"逐级从 S2S 里拿走，拿走得越多，S2S 越只剩"念对、接得住"。

### 0.1 证据表

| 来源 | 对比 | 数字 | 口径 |
|---|---|---|---|
| 总结 §3.1 | 63 句冻结盲测，谁选工具 | 纯规则 54%（训练句 100%）/ S2S 原生 FC 81% / 小文本 LLM 84% | **实测**。81% 与 84% 在 63 句上约差 2 句，差异不显著（**推算**，KM 2.7） |
| FE §2.3（QW customer-service benchmark，tau2 EVA 航空） | 同一任务集三路 | 纯 S2S 44% / S2S + Harness 62% / 纯文本大模型 68% | **仓库自述**。笔记注明是纯文本评测，不含 ASR / TTS——差距来自模型本身，不是"听" |
| HC §0、KM 2.10 | 开源半级联理解端推理能力 | Step-Audio 2 mini Big Bench Audio 54.8；Qwen3-Omni"强"但要 80 GB 卡 | **仓库自述** |
| 总结 §3.2 | 人设写"没被告知的就说不清楚，不要编" | 模型仍自信地编出年份、产量等细节；RAG 通道下也会在资料外补细节 | **实测**（定性） |
| 总结 §3.1 | 模型把"好的"判成"开始"类写操作 | 被原话门槛拦下 | **实测**（定性） |
| 总结 §5.4 | 长对话 | 上游只保留约 20 轮；用会话 id 接续后"历史看得到，模型不用"（1/6） | **实测** |

两点读法：第一，**选工具这种窄任务上 S2S 并不差**（81% 对 84%），差的是多步推理、长上下文使用、"不编"这类要求（44% 对 68%、编造、20 轮）。第二，Harness（外围工程）能把 44% 拉到 62%，但到不了 68%——**外置能补大部分，补不满**（见 §2）。

### 0.2 四个代表实现：都在把智力移出 S2S

| 实现 | S2S 做什么 | 智力在哪 | 出处 |
|---|---|---|---|
| ORA chat-supervisor | 只做问候闲聊、请重复、收集参数（prompt 白名单）；其余一律调唯一的委派工具 | 后台 gpt-4.1 + 工具循环 | ORA Q1 |
| LK GPT-Live `delegation="responses"/"client"` | `responses` 模式下"语音模型本身不推理、不调工具" | 服务端后台 Responses 模型，或应用自己的 LLM（`append_commentary` 回前台） | LK Q7 |
| PC `OpenAILiveLLMService` + `BackendLLMWorker` | 前台全双工模型决定何时委派 | 后台任意 LLM；commentary（要说的）/ thinking（静默上下文）双通道 | PC Q6 |
| QW `spawn_thinking` | 能答就答，要后台执行才委派；人设与规则分离 | 后台 ACP agent；前台归类四条件：延迟预算 < 2 s、无多步编排、状态前台自有、风险低 | QW §2.1 |

实践笔记里的对应物是"角色 S2S + 外置判定层"（KM 1.1）和"规则短路 + S2S FC + 修正层 + 门槛"（总结 §3.1）。四个开源实现都只做了"委派"这一种外置；**事实通道、规则修正层、写操作门槛在调研里都没有对应物**（架构 §1 末尾两段）。

## 1. 六个手段（按"从 S2S 里拿走多少"由少到多排序）

| # | 手段 | 从 S2S 拿走什么 | S2S 还剩什么 |
|---|---|---|---|
| 1 | 缩小决策空间 | 大部分"选什么"的选项 | 在小集合里选 |
| 2 | 事实不靠它 | "知道什么" | 念对 |
| 3 | 规则短路 + 修正层 + 写操作门槛 | "决定做什么"的最终权 | 提议 |
| 4 | 前台 / 后台分工 | "想清楚、组织语言" | 在场、承接 |
| 5 | Prompt 结构 | —（不拿走，而是让剩下的更稳） | — |
| 6 | 评测驱动迁移 | 按失败类别逐项搬走 | 它实测做得好的那部分 |

手段 5 不移走能力，放在第 5 位是因为它的作用依赖前四个先把"该拿走的"拿走；手段 6 是决定 1–4 各做多少的机制。

### 1.1 缩小决策空间

**做法**：三种力度，由弱到强。
- **单一委派工具 + 白名单**：S2S 只看得到一个"交给后台"的工具，prompt 里用白名单列出它可以自己处理的几类（问候、请重复、收集参数），其余一律委派（ORA Q1）。后台工具的定义若要让前台知道，用非 JSON 的描述写进 prompt，避免模型直接去调（ORA 用 YAML，仓库自述理由）。
- **按阶段收窄可见动作集**：阶段决定本回合可见的动作 = 阶段动作 ∪ 全局动作 ∪ 前置已满足的动作（03 §8.2 ②、§8.3；pipecat-flows 按节点换工具集；LK `AgentTask` 确认工具只在前置步骤后注入，FE §1.4）。
- **外置意图判定，S2S 只出声**：意图由自己的策略层（规则或小文本 LLM）判，S2S 不选工具，只按注入的事实和指令说话（KM 1.1"角色 S2S + 外置判定层"）。

**机制**：选项越少，S2S 能犯的错越少；"不可见"比"可见但被拦"更稳（FE §1.4："那一步根本没有这个选项"）。

**依据**：ORA 白名单委派（仓库自述 README："通过增加白名单项调整决策边界"）；pipecat-flows、LK `AgentTask`；实践笔记的外置判定层普通回合 P50 1.2 s、逐字念 0.6–0.7 s、RAG 1.0 s（**实测**，总结 §6）。

**适用条件**：
- 白名单委派：S2S 的主要失败是"该委派不委派 / 自己瞎答"。委派判断本身仍由 S2S 做，准确率未知（BP A2 风险：原生 FC 盲测 81% 可作参照）。
- 阶段收窄：任务有明确阶段；全局动作（闲聊、追问、纠正、取消、停止）必须在任何阶段保留，否则会把用户锁死（03 §8.3）。
- 外置判定：S2S 的工具选择明显差于小文本 LLM，或需要可解释的判定。

**代价**：
- 委派白名单越窄，工具回合越多，而工具回合是 S2S 最慢的回合（§3）。
- S2S 上换工具表要 `session.update`，Gemini 改工具要重连（KM 2.10）——所以**阶段收窄不改上游工具表**，在 S2S 输出之后校验：调了阶段外工具就不执行、本地直念引导话术、不再生成（03 §8.2 "阶段外调用的处理"）。
- 外置判定的规则版盲测只有 54%（**实测**），小 LLM 版多一段约 0.84 s 的 P50（**实测**）；普通回合从 0.87–0.96 s 变成 1.2 s（**实测**）。

**怎么落地**：03 §8.1 ②（阶段过滤）、§8.3（阶段与全局动作）、§3.2 决策表（委派即 A2 路线）；阶段外调用的收口按 03 §8.2；A 类选择器接口见 03 §8.2 ③ `ToolSelector` 可替换（规则 / 小文本 LLM / S2S FC）。

### 1.2 事实不靠它

**做法**：S2S 不"知道"任何业务事实，只"念"agent 侧给的。四条通道（05 §2.4、KM 3.7）：
- **逐字念**：位置、时间、数字、状态结果由 agent 侧渲染成最终文本，本地 TTS 直念（或上游 say，待 P0-13）；
- **上屏**（B 类）：清单、多选项、需确认的字段上屏，语音只说要点；
- **RAG 注入**：讲解类给分层资料卡（简介 / 正文 / 细节，每次只给当前层），附"只用资料内信息"的约束；
- **状态块**：自己的数据（进度、用户选择、用户告知的硬信息、当前阶段），放系统提示末尾，版本化（05 §2.2）。

替代方案也是事实：做不到时由工具从数据算出最多两个可行替代，模型只负责说出来（03 §7.4）。

**机制**：把"不编"从模型的品质要求变成结构——模型没有机会编，因为关键内容根本不经过它的生成。

**依据**：总结 §3.2（人设约束挡不住编造；逐字念首音 0.6–0.7 s、RAG 约 1.0 s，**实测**，逐字念的计时起点待核，BP A.5）；状态块使多轮用例 66/80 → 76/78、"开始吧"组 8/16 → 15/16（**实测**，总结 §5.4）；QW 把"人设里涉及事实的内容一律无效"写成对模型可见的规则（QW §2.1、FE §4.2）；替代方案随结果下发（FE §5 模式 1，pipecat-flows 餐厅示例 `alternative_times`）。

**适用条件**：事实可枚举、有数据源；关键事实（数字、时间、位置、状态）必须走逐字念，不得只走 RAG。

**代价**：
- 逐字念是模板化话术，只适合结构简单的结果（BP A1 局限）；
- 本地 TTS 直念与 S2S 原生音色不一致，除非上游 `response.say` 为 `native` 且逐字（04 §2.2.4）；
- 状态块每次更新都会让上游整段重新预填：未命中缓存的输入 ×3.2，粗粒度更新首音 +80–200 ms，每轮都更新 +150–270 ms（**实测**，KM 3.4）——所以分"立即生效 / 懒生效"两层。

**怎么落地**：03 §3.1 A1（收口直念）、§3.2 决策表 #1/#8（verbatim / screen）、§7.1（回传内容）、§7.4（替代方案）；05 §2.2（状态块）、§2.4（事实通道格式）、§6（注入通道选择）。

### 1.3 规则短路 + 修正层 + 写操作门槛

**做法**：模型只提议，执行权在 agent 侧。三层各管一段（03 §8.1 的顺序：① 规则短路 → ② 阶段过滤 → ③ 模型提议 → ④ 修正层 → ⑤ 实体解析 → ⑥ 门槛链）：

| 层 | 位置 | 管什么 | 例 |
|---|---|---|---|
| 规则短路 | 模型之前 | 确定的、危险的、必须快的 | 噪音静默、明确控制指令、紧急出口、转人工 |
| 修正层 | 模型之后 | 按当前状态纠正模型的提议 | 无进行中任务时把"确认完成"改成引导开始；刚问过问题时两字回答不算噪音 |
| 写操作门槛 | 执行之前 | 有副作用的动作 | 意图属于允许集 → 原话命中"开始 / 提交"类词且排除"怎么开始" → 重读后端状态 |

实体解析里"模型编的全名与原话冲突时以原话为准"（03 §8.2 ⑤）也属于这一类：参数不信模型，信原话和数据。

**机制**：规则擅长"确定"（训练句 100%）、不擅长"泛化"（盲测 54%）；模型反过来（81%）。两者各管一段，门槛独立于两者。

**依据**：总结 §3.1（三组盲测数字，**实测**）。**调研里没有一个仓库做全三层**：xiaozhi 有模型前的规则（退出词、唤醒词精确匹配，XZ §2.4）；pipecat-flows 有 handler 内校验，最接近修正层但不是（FE §1.4）；ORA 没有执行前门槛，"能不能退货"由 LLM 决定，SDK 的 `needsApproval` 也没用上（ORA Q5）；LK 的确认工具在前置步骤后才注入，是结构化门槛的一半（KM 2.8）。

**适用条件**：凡是有写操作、有"确定且危险"的输入类别的产品都适用。纯闲聊产品只需要规则短路的噪音一条。

**代价**：
- 规则要维护，"每类说法加规则"（总结 §6）；
- 修正层是事后兜底，事前收窄（§1.1）优于它，二者互补不替代（FE §1.4）；
- 门槛第 2 道依赖转写文本，转写错时只能拒绝、不能纠正（§2.1）；
- 噪音规则只能在模型尚未开始调工具或说话时生效，否则会吞掉被判停切成两段的真话（总结 §3.1）。

**怎么落地**：03 §8（全节）；门槛拒绝回传 `ok=false` 收口、话术本地直念（03 §7.2 第 5 条）；写操作不委派给后台模型（03 §3.2 #7）；执行前再查代际（03 §5.2）。

### 1.4 前台 / 后台分工

**做法**：S2S 当前台，负责在场、承接、闲聊；需要想清楚或组织语言的事交给后台文本模型。委派协议（03 §6.1）给后台：自己的 ASR 定稿文本（优先）或前台复述的"最后一句要点"、状态块、最近 K 轮（assistant 部分用用户实际听到的文本）、只读工具子集、语音化约束、截止时间。后台回前台分通道（03 §6.2）：

- **speak**：要说的正文，流式按句切出；
- **context**：中间事实、工具细节，只进上下文不出声；
- **terminal**：`done / failed / timeout / empty`，据此收口前台调用。

这对应 PC 的 commentary / thinking 双通道（PC Q6）和 LK GPT-Live 的 `append_commentary` / `append_thinking`（LK Q7）。

**延迟陷阱**：委派本身不省延迟，**只要结果交回 S2S 再生成，就至少多付一次约 1.2 s**（**实测**，总结 §3.4）。

| 做法 | 延迟 | 口径 |
|---|---|---|
| ORA chat-supervisor：function output + `response.create`，前台再生成 | 填充语播完后还要约 2 s | **仓库自述**（README） |
| 照搬 chat-supervisor 到实践笔记的场景 | 有内容首音 2.6–3.5 s | **推算**（BP A.1） |
| QW `spawn_thinking`：短工具走后台 | 从说完到工具开始执行 +2.05 s（1.32 → 3.36 s），不含回复音频 | **仓库自述**（92 回合 bench） |
| **后台流式文本 → 本地 TTS，回传实际播出的文本，不再生成**（03 A2） | 不投机 1.4–1.8 s；识别定稿即投机起跑 1.0–1.3 s | **推算**；A-E4 门槛 P50 ≤ 1.3 s |

正确做法是最后一行：后台产出的文本直接进本地 TTS，前台调用只收口不再生成（03 §7.2）。LK GPT-Live 的 commentary 仍是"前台用自己的话说"（≤ 500 token），是否也付再生成的时间未测。

**依据**：§0.2 四个实现；BP A.1 第 2 条。

**适用条件**：
- 回合需要多步推理、查询后组织语言（讲解、推荐）；
- 上游支持静默收口（`tools.auto_reply_after_result = no`，或有 `flag` 类静默选项，04 §2.2.5）；否则后台文本出不了本地 TTS 以外的路，结果要么退回 A0，要么改半级联（03 §3.3）。

**代价**：
- 两份上下文，指代要两边对得上（BP A2 风险）——所以实践笔记的做法是给后台状态块和最近几轮，不像 QW 只给自包含 objective（03 §6.1）；
- 两种声音：S2S 原生音色与本地 TTS 不一致（架构 §3.2 推论一）；
- 投机起跑会浪费没用上的调用，并可能和前台直答抢话筒（靠仲裁器的代际和租约挡，03 §6.3）；
- 委派必须可取消，失败 / 超时 / 无输出时前台一定回一句，且兜底话术本地直念而不是交给前台再生成（03 §6.4）；
- 写操作永不委派（03 §3.2 #7）；后台只拿只读工具。

**怎么落地**：03 §3.1 A2、§6（全节）、§7.2；投机 03 §6.3；B 类高风险回合的 speak 通道逐句过出声前护栏（03 §6.2）。

### 1.5 Prompt 结构

**做法**：
1. **人设与规则分离，规则优先**：人设只写身份 / 性格 / 语域；路由、边界、语音规则写在规则里，并写明"人设里涉及工具、路由、事实的内容一律无效"（QW §2.1、FE §4.2 引 `PROMPT.md:15-18`）。拼接顺序固定：人设 → 规则 → 状态块（05 §2.3）。
2. **硬规则必须可检查**：每轮一两句、数字口语化、先结论后理由、一次只问一个问题、禁 markdown / 列表 / emoji；禁用词表进测试；人设版本进 trace（总结 §4.6；05 §2.3）。
3. **few-shot**：会话开始时注入临时 few-shot（如"讲个故事" → 调工具），排在历史前（XZ §2.4）。
4. **强制工具化**：xiaozhi 的 `direct_answer` 虚拟工具——不需要工具时也把回复写进它的参数，让模型每轮都走"选工具"这一步（XZ §2.4）。
5. **能力边界与"不先说自己不行"成对写**：边界写清楚，但在边界之内先调工具，工具明确返回不可用才说明限制（FE §5 模式 3、4）。
6. **承接语不靠 prompt**：ORA 要求"调用前必须先说一句"，代码层无兜底，模型跳过就干等；改用本地旁路提示语，不进模型（架构 §1 原则 9）。

**机制**：弱模型最先丢的是"长段落里夹着的约束"；把约束集中、分级、可测，丢了能被测出来。

**依据**：见各条出处。实践笔记的"硬规则可检查 + 禁用词进测试 + 人设版本进 trace"比调研的所有仓库都严（FE §4.2）。

**适用条件**：所有路线都适用。`direct_answer` 式强制工具化**在 S2S 上不直接适用**：S2S 直接出音频，强制每轮走工具等于把每个回合都变成最慢的工具回合（§3）；它适用于级联、半级联或后台文本模型。S2S 上的等价物是"白名单 + 阶段外调用校验"（§1.1）。

**代价**：prompt 越长预填越贵、缓存越重要；人设变更只在新建会话时生效，不在会话中途更新（05 §2.3 规则 3）。few-shot 占上下文，也可能被模型当作真实历史。

**怎么落地**：05 §2.3（人设结构）；FE §4.1 共同约定表；BP C4（缺的三项：音频 / 文本两档确认强度、听不清时的话术分级、语域切换信号）。

### 1.6 评测驱动迁移

**做法**：外置到什么程度不是拍脑袋定的，而是按失败类别一项项搬：
1. **冻结盲测集**：一组从未用来调参的句子，每个方案在同一组上比（总结 §7；06 §7.1）。训练句 100%、盲测 54% 的差距只有它能暴露。
2. **按失败类别归因**，不按总分：指标分开命名——动作命中、槽位命中、无工具轮正确率、写操作误触率（BP C3）；judge 拆成 understanding / honesty / recovery / efficiency / brevity 的逐轮二元判定（BP C3）。
3. **按类别决定搬到哪**：确定且高频的 → 规则短路；依赖状态的 → 修正层或阶段收窄；有副作用的 → 门槛；需要推理 / 组织语言的 → 后台；编造类 → 事实通道。S2S 做得好的类别留在 S2S。
4. **同一套用例跑多条路径**：参照 QW bench 的三路对比（纯文本 / S2S / S2S + Harness），差值就是"智力差"和"外置补回了多少"（FE §2.3）。
5. **按版本统计**：`prompt_version` 前缀区分链路，后缀带人设 / 工具表 / 状态块版本；换一版不用改门禁，按前缀分批对比（总结 §7；06 §3.2）。

**机制**：避免两种错误——把 S2S 已经做得好的事外置（白付延迟），或把它做不好的事留着（靠 prompt 祈祷）。

**依据**：总结 §7、§8 原则 11；QW bench 的指标分开命名、参数匹配走规则归一化（FE §2.3）；ASR 噪声变体分开报（BP C3）。

**适用条件**：必须先有 trace 和冻结集。没有尺子时，不要做 §1.4 这类大改动（BP"总体顺序"）。

**代价**：样本集和 judge 本身要建、要校准（C-X0、C-X1）；有竞态的脚本没有通过率就不能作门禁（06 §8.2）。

**怎么落地**：06 §3.2（版本字段）、§3.3（决策字段）、§5.1（L0）、§6（rubric）、§7（冻结集）、§8（门禁）。

## 2. 补不了的三样

外置能把 44% 拉到 62%，到不了 68%（§0.1）。剩下的主要是这三样。

### 2.1 听错

**为什么补不了**：S2S 的"听"在模型内部。所有外置层（规则、修正层、门槛、委派）吃的都是转写文本，而转写可能来自同一个模型、可能晚于 function call 到达（ORA Q1(b) 的转写竞态）。转写错了，外置层只能拒绝，不能纠正。

**减轻手段**：
- 上游前音频门控：停顿压缩、短按过滤、补充窗口，减少切段和误触（BP C1）；
- 并行跑自己的 ASR，委派时优先用它的定稿（03 §6.1 `transcript` 优先于 `last_utterance_gist`）；
- 状态辅助：刚问过问题时两字回答不算噪音（总结 §3.1）；
- 话术分级：意图清楚就做 → 猜一个请确认 → 请重说（FE §4.1；BP C4 列为缺项）；
- 写操作两档确认：音频回合复述确认，屏幕 / 文本回合不需要（BP C2；03 §8.4）；
- 评测：冻结集每句生成 ASR 噪声变体（同音字、截断），原句与变体分开报（C-X8）。

### 2.2 讲解时补细节

**为什么补不了**：只要让 S2S 自己组织语言（RAG 通道），它就会在资料外补细节（总结 §3.2，**实测**）。而 S2S 出声前没有文本审核窗口：文本 token 只比声学早几十毫秒（KM 2.10；架构 §3.2），护栏只能事后判转写再纠偏，ORA 就是这么做的，命中时"这段话的大部分已经播出去了"（ORA Q5）。

**减轻手段**：
- 关键事实（数字、时间、名字）不走 RAG，走逐字念（05 §2.4 注意）；
- 资料分层，每次只给当前层，减少可发挥的空间（总结 §3.2）；
- 讲解改走 A2：后台文本生成 → 进 TTS 前做同步检查 → 本地 TTS，代价是失去 S2S 原生表现力、两种声音（§1.4）；
- 半级联或 Step-Audio 式单模型按回合选"出文本还是出语音"：需审核的回合只出文本（KM 2.10；架构 §3.2 推论二）；
- B 类高风险回合禁用 S2S 直出和 A0（03 §3.3 第 2 条）。

### 2.3 长对话管理

**为什么补不了**：模型怎么用长上下文是它内部的事。上游约 20 轮后丢早期信息；会话中途插入历史或状态"基本不看"；用会话 id 接续后"历史看得到，模型不用"（1/6）；逐条插入历史 0/6（**实测**，总结 §5.4）。

**减轻手段**：
- 硬信息（称呼、陪同人、特殊模式）收进状态块，不依赖模型记忆（05 §5.4）；
- 历史只在建会话时带入（6/6，**实测**）；会话重建器把"重建"变成常规路径，接近轮数上限、状态粗变化、定时回收都走它（05 §4）；
- 摘要在 agent 侧做，输入是已播放文本，不对摘要再摘要（05 §5）；
- B 类一任务一会话，结构化状态和摘要是上下文主体（架构 §3.2；05 §5.7）。

## 3. 代价：外置越多，工具回合越多

S2S 的反直觉之处：**普通回合最快（0.87–0.96 s），工具回合最慢（有内容首音 2.1–2.3 s）**，因为多走一圈"回传 → 再生成"约 1.2 s（**实测**，总结 §3.4、§6）。而手段 1、2、4 的外置方式恰恰都是"让 S2S 调工具"。所以：

> **外置必须与"收口不再生成、本地直念"同做。** 否则每搬走一项智力，就多付一次 1.2 s。

具体地：每个外置出去的调用都要收口（回传或明确终止，悬着的调用导致约 21% 重复调用，**实测**，总结 §5.2），但收口和再生成是两件事（架构 §1 原则 1）；结果由本地念（A1）、由后台文本经本地 TTS 念（A2）、或进度即收口（A3），只有 A0 兜底才让模型再生成（03 §3.1、§7.2）。

### 取舍表：外置程度 vs 延迟 vs 准确

| 外置程度 | 典型形态 | 普通回合首音 | 工具回合有内容首音 | 决策准确 | 事实可控 | 表现力 / 声音 |
|---|---|---|---|---|---|---|
| 0 不外置 | S2S 原生 FC + 回传再生成（A0） | 0.87–0.96 s（实测） | 2.1–2.3 s（实测） | 工具命中 81%（实测） | 中（依赖 prompt） | 最好，单一声音 |
| 1 事实外置 + 收口直念 | + 手段 2 + A1 | 同上 | ≈ 1.1 s（推算，A-E2 门槛 P50 ≤ 1.1 s） | 同上 | 高 | 直念段换本地 TTS 声音 |
| 2 + 决策护栏 | + 手段 1（阶段校验）+ 手段 3 | 同上；规则层约 1 ms（实测） | 同上 | 写操作误触下降（待 C-X7） | 高 | 同上 |
| 3a + 委派后台，交回再生成 | ORA / QW 形态 | 同上 | 2.6–3.5 s（推算）；QW 到工具开始 +2.05 s（仓库自述） | 后台强 | 高 | S2S 单一声音 |
| 3b + 委派后台，本地直念 | 03 A2 | 同上 | 1.4–1.8 s，投机 1.0–1.3 s（推算） | 后台强；委派召回待测（A-E4 门槛 ≥ 81%） | 高，可出声前审核 | 两种声音 |
| 4 外置意图判定，S2S 只出声 | 角色 S2S + 外置判定层 | 1.2 s（实测） | 逐字念 0.6–0.7 s / RAG 1.0 s（实测，起点待核） | 规则版 54%（实测）；小 LLM 版 84% 但 +0.84 s P50（实测） | 高 | 最好 |
| 5 半级联 | S2S 或音频 LLM 只出文本 → 自己的 TTS | 未实测；多一段 TTS 首包（推算） | 与级联相近，只付文本 LLM 的 TTFT | 取决于底座；Step-Audio 2 mini 推理弱 | 最高（文本先于语音） | 失去原生表现力，声音统一 |

读法：**1 和 2 几乎是免费的**（延迟不增或下降），应当默认做；3b 是智力和延迟的最优折中，但依赖上游支持静默收口；4 和 5 用普通回合的速度或表现力换可控性。

## 4. 决策树：给定一个 S2S 上游，外置到什么程度

输入是能力声明里的四个能力位（04 §2.2；QW §2.6 的命名在括号里），全部由 P0 探针填写。

1. **能调工具、能被客户端驱动吗？**（`tools.calling`；`response.client_initiated` / `clientResponses`）
   - `none` 或 `no`（如 MiniCPM-o）：委派、结果注入、直念收口都不可用（E2E Q4）。只能当闲聊前台，或用外置判定 + 每轮初始化指令；有工具回合的产品不选它，转 5（半级联）。
   - `native` / `prompted`：进入 2。
2. **静默收口可用吗？**（`tools.auto_reply_after_result` + `tools.silent_close`，P0-1）
   - `no`（`by_omission`，如 OpenAI、DashScope、StepFun）或 `yes` + `flag`（Gemini `SILENT`、Ultravox `listens`）：A1 / A2 成立，**可以放心外置**：手段 1–4 全做，工具回合走 A1 / A2 / A3。进入 3。
   - `yes` 且无静默选项（如 LK 插件里的 GPT-Live、Doubao 待测）：每次外置都付再生成。只做不增加工具回合的外置——手段 2 的状态块和资料注入、手段 3 的规则短路（在模型之前，不经工具）、手段 5；需要后台智力的回合改半级联或接受 A0（03 §3.3 第 1 条）。
3. **有按回复指令吗？**（`response.overrides.instructions` / `perResponseInstructions`，P0-5）
   - 有且不进历史（如 DashScope）：外置判定 + "S2S 只出声"（程度 4）可以按回合下发指令而不污染历史、不破坏会话前缀；状态块"立即生效"层优先随回复下发（BP B.4）。
   - 没有，或只能插入持久 item（如 StepFun）：指令会进历史、每次改会话配置要整段重新预填（×3.2），**不要按回合改指令**；判定结果改用工具结果的形式送进去（function output），或用程度 1–3。
4. **会话可变吗？**（`config.update.*` / `mutableSession`，P0-6）
   - `live_full`：状态块可以在两轮之间更新，但按两层生效控制频率（05 §2.2）。
   - `next_session`（如 Google Live、MiniCPM-o）：建会话后改不了指令。状态块"立即生效"层只能靠会话重建器（05 §4）；会话中能动态约束 S2S 的只剩工具结果——因此**更依赖工具层的外置**（阶段校验、修正层、门槛），prompt 只放稳定的人设和规则。
5. **以上都不理想**：转半级联（KM 2.10：开源首选 Step-Audio 2 mini，质量上限参照 Qwen3-Omni），外置由"文本先于语音"在结构上保证，代价见 §3 程度 5。

补充两个次要能力位：`response.say = native` 且逐字时，直念可以不换音色（04 §2.2.4，P0-13）；`config.append_channels` 含 commentary / thinking 时（仅 GPT-Live），可以用 LK / PC 式委派，但 commentary 仍由前台转述，是否付再生成时间要测（§1.4）。

## 5. 与两类架构的关系

### 5.1 A 类（无界面硬件，S2S 为主）怎么配

A 类的模型形态是"S2S 优先，事实和工具结果走本地直念"（架构 §0）。风险低，护栏是"不编事实"，所以外置的重点是**事实和写操作，不是讲话的每一句**：

| 手段 | A 类配置 |
|---|---|
| 1 缩小决策空间 | 工具表建会话时给全（05 §6.3），阶段收窄在 S2S 输出后校验；不做"单一委派工具"——A 类闲聊和简单讲解本来就该 S2S 直出 |
| 2 事实不靠它 | 状态、进度、位置类走 A1 直念；讲解走 RAG 分层卡；替代方案随结果下发，最多两个选项 |
| 3 三层 | 全做；门槛第 2 道失败时念一句确认问题（03 §8.4） |
| 4 前台 / 后台 | 只用于需要组织语言的工具（A2）；秒级写工具用 A3 |
| 5 Prompt | 硬规则可检查 + 禁用词进测试；人设 → 规则 → 状态块 |
| 6 评测 | L0 冻结集 + ASR 噪声变体；三种选择器同集对比（C-X8） |

没有屏幕，沉默即故障：外置导致的每个等待都要有本地旁路提示语兜住"有声音"，但提示语不能冒充"有内容"（总结 §3.3、§8 原则 4）。

### 5.2 B 类（有界面，三角权衡）里 S2S 分支的边界

B 类按回合类型和风险等级在 S2S / 级联 / 半级联之间选路（架构 §3.2）。从智力角度看，**S2S 分支的边界就是"这个回合不需要智力"**：

- **留在 S2S**：寒暄、安抚、过渡、承接句——低风险、重体验，失败类别里没有"推理"和"事实"。
- **离开 S2S**：涉及事实、数字、方案、建议的回合走文本先于语音；工具回合无论哪条路线，结果都由文本层组织、本地 TTS 出声，S2S 只收口不再生成；高风险回合禁用 A0，speak 通道逐句过出声前护栏（03 §3.3、§6.2）。
- 屏幕是 B 类特有的外置通道：清单、多选项、需确认的字段上屏，语音只说要点（手段 2），这比 A 类多拿走一块"组织语言"的负担。
- 两类的区别不在手段，而在**默认值**：A 类默认留在 S2S、按失败类别往外搬；B 类默认离开 S2S、按体验需求往回放。
