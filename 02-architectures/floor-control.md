# 话筒归属：输出仲裁与打断冲刷

> 状态：草稿
> 最后更新：2026-10-01

**要点**：语音 agent 里想出声的东西远不止模型回复：本地合成的工具结果、工具执行时的提示语、后端推来的事件播报、定时提醒、错误兜底话。它们需要一个仲裁器回答"此刻谁可以出声、被打断后怎么办"。几个开源项目和一份实践笔记独立得到了相近的设计：**同一时刻只授权一个发言者**；用单调递增的**代际（generation）**而不是"清空队列"来过滤旧输出；长生命周期任务每次出声前**重新领取话筒租约**；非本回合的播报只在**以播放回执为准的空闲窗口**插话；打断时按输出种类**冲刷**，且冲刷之后零音频。

---

## 1. 这个决策是什么

```
  模型回复（上游音频流）─┐
  工具结果（本地 TTS）───┤
  提示语（预合成）───────┤   OutputRequest{kind, origin, priority, generation, ...}
  事件播报 / 提醒 ───────┤
  错误兜底话 ────────────┘
                         ▼
          ┌──────────────────────────────────┐
          │ 仲裁器                            │
          │  · 一个话筒 + 一个有界等待队列     │
          │  · 当前代际 G                      │ ◄── 回合状态机：新回合 / 打断 → G+1
          │  · 插话窗口（看播放回执）          │ ◄── 设备回执：started / ended / interrupted
          └───────────────┬──────────────────┘
                          │ 授权（带租约 = lease_id + G）
                          ▼
               下行出口：每帧发出前再比一次代际
                          ▼
               设备 / 客户端：按 turn_id 和本地播放代际二次过滤 ──► 扬声器
```

仲裁器**授权的是"出声"，不是"生成"**。上游可以提前生成、本地 TTS 可以提前合成，但只有持有授权的请求能向下游发音频帧。这让"提示语和正文排队，不串行等待"成立：一份实践笔记实测，工具结果排在提示语后几乎不等待（P50 0，P90 0.2 s），双声为 0。

仲裁器不管说什么（那是模型、工具层、事实通道的事），也不管谁算"用户开口"（那是回合状态机和判停的事）。它只消费这些事件。

---

## 2. 输出种类

一种实践把输出分成三类，种类决定默认行为：

| 属性 | `cue` 提示语 | `speech` 本回合回复 | `narration` 播报 |
|---|---|---|---|
| 例子 | "我查一下路线。" | 模型回复、本地直念的工具结果 | 到点提醒、后台任务完成、设备事件 |
| 绑定回合 | 是 | 是 | 否，授权时绑定 |
| 需要插话窗口 | 否 | 否 | **是** |
| 打断时冲刷 | **否**（已在播的放完） | 是 | 是 |
| 被用户打断后 | 丢弃 | 丢弃 | 视为已送达，不重播 |
| 进上下文 | 否（旁路，不进模型） | 按播放位置截断后进 | 按来源 |

`cue` 不冲刷的理由是它很短、本地播放。但旧回合的、还没开播的 `cue` 仍然被代际过滤丢掉：一个旧回合的"我查一下路线"在新回合开头冒出来没有意义。

**优先级只决定排队顺序，不决定抢占**。除了 `critical`（转人工、紧急出口这类系统级打断），任何请求都不能打断正在出声的授权，只能排队。种类的约束优先于优先级：一条高优先级的 narration 仍然要等插话窗口。

---

## 3. 代际

### 3.1 什么时候 +1

只有三种情况：

1. 新用户回合开始（任一边界来源）。
2. 用户打断。
3. `critical` 抢占。

打断和新回合同时发生时只 +1 一次。回合正常结束、工具返回、会话重建、narration 开始或结束都**不** +1。

### 3.2 在哪里比较

任一处 `request.generation < G` 就丢弃：

1. **入队时**：迟到的请求直接丢。
2. **授权时**：排队期间代际变了的丢。
3. **每个下行帧发出时**：已授权但还在生成的输出（尤其是上游音频流），每帧都比。

第三处专门对付**上游迟到帧**：上游 cancel 之后可能仍推来音频 delta。消费端（设备下行出口、本地 TTS、客户端播放器）再按代际或请求 id 做第二道过滤；消费端丢了帧，说明中心过滤漏了，应当当作缺陷信号。

narration 入队时没有代际，授权时由租约盖上**当时的** G，所以两分钟前产生的后台结果不会因为"出生代际旧"而永远播不出去，但开播之后就和 speech 一样受代际约束。

### 3.3 为什么不用"清空队列"

一次性清空只处理"已经在队列里"的东西，处理不了"清空之后才到"的帧。Pipecat 的打断是一次性清空各队列里的可打断帧，不按回合 id 过滤，上游迟到的帧会被当作新回复（据读代码，是否真会发生待验证）。代际把"新旧"变成一个可比较的数，任何时候到达的帧都能判。

## 4. 话筒租约

租约 = (lease_id, generation)，授权时签发。持有者发帧时必须带租约。

**长生命周期任务出声前必须重新领取**。事件分发循环、后台任务的回帖协程、定时器，这些对象活得比一个回合长，不得缓存租约；每次要出声都以一条新请求入队，授权时拿到当前代际的新租约。一份实践笔记记录的反例是一个难查的 bug："每个连接只有第一轮有声音"：上游事件的分发循环拿着第一轮的租约出声，从第二轮起全部被过滤。

跨连接时还有一种"播报领取"：同一条 narration 在多个连接或断线重连之间只能被一个连接领取（qwen-audio-agent 的做法：领取 TTL 60 s，每 TTL/3 续期，断开只释放不算送达）。这和话筒租约、会话归属是三件不同的事，见 [state-and-context](state-and-context.md)。

---

## 5. 插话窗口

narration 只在窗口打开时授权。窗口关闭 ⇔ 以下任一成立：

1. 用户在说（按键模式下即按键按住；开放麦下判停进行中也算）。
2. 回合未结束（模型还在说、或在等工具续答）。
3. 有已下发但还没收到 `playback.ended / interrupted` 的音频。

关键约定：

- **以设备的播放回执为准**，不以服务端生成完或发完为准。设备有缓冲、服务端超前几百毫秒，不看回执就会把播报插进一句话的尾巴。
- 窗口打开后再静默一小段才授权（qwen-audio-agent 默认 350 ms）。
- 被挡住的 narration 定时自检（qwen-audio-agent 每 1 s），不只靠事件驱动，因为事件可能丢。
- 回执丢失要有兜底：开始回执超时视为未送达、稍后重试（绝不叠出第二段）；结束回执超时按"剩余时长 + 2 s"视为播完。

## 6. 冲刷

| | 正在播（持有授权） | 排队中 |
|---|---|---|
| cue | 不冲刷，放完 | 低代际的被过滤 |
| speech | 冲刷 | 丢弃 |
| narration | 冲刷，按规则决定是否重试 | 保留，等下一个窗口 |

动作序列：撤销授权（代际已 +1）→ 上游音频流：通知上游 cancel，并按回执换算的播放位置 truncate → 本地 TTS：flush → 向设备发 `flush.start`，清空自己的发送队列后发 `flush.end` → 设备丢弃这些回合已缓冲未播的音频。**硬契约：`flush.end` 之后，被冲刷的回合零音频**（TEN 的 TTS flush 契约是同一思路）。

被打断后**不重播**：用户打断的输出视为已送达，无论种类（qwen-audio-agent 的进度播报注释："重播同一段独白比省略它更打扰"）。非用户原因的中断（连接断开、系统冲刷）才按上限重试。

队列要有界：长回答加慢设备会把队列撑大，超过上限丢弃最低优先级、最早入队的请求并记日志。

---

## 7. 适合与不适合

- **需要中心仲裁**：有多个出声来源（模型 + 本地合成 + 提示语 + 事件播报）；有后台任务或设备事件会在回合之外出声；S2S 上游可能推迟到帧。
- **可以从简**：纯级联、只有模型回复一个来源、没有主动播报的原型。此时"取消任务 + 清队列 + 一个回合级 id 过滤"已经够用。

---

## 8. 关键取舍

| 取舍 | 说明 |
|---|---|
| 中心仲裁 vs 各来源自行判断 | 中心仲裁保证双声为 0、规则只写一份；代价是所有出声都要包成请求、多一层排队 |
| 代际 vs 清空队列 | 代际能处理迟到帧；清空实现简单但有漏洞 |
| 回执驱动 vs 估算 | 回执准确但依赖设备实现；不支持回执时退化为估算，并在 trace 标出 |
| 不重播 vs 重试 | 用户打断不重播是体验选择：用户可能一句没听到，但上下文里有，可以追问。一定要让用户知道的内容不该走 narration |
| 不可打断片段 | 只给极少数安全话术（限长数秒）；不要用"不可打断"保护写操作，写操作靠执行前检查代际 |

## 9. 开源项目怎么做

| 项目 | 做法 |
|---|---|
| [livekit-agents](../04-projects/frameworks/livekit-agents.md) | 优先队列 + 串行调度协程，同一时刻只授权一个 `SpeechHandle`（优先级 LOW 0 / NORMAL 5 / HIGH 10，只影响调度顺序）；异步工具结果等 `wait_for_idle`（没在播、用户没说、判停不在进行）再回帖 |
| [qwen-audio-agent](../04-projects/frameworks/qwen-audio-agent.md) | 串行输出队列 + `whenIdle` + 响应代际 + 按 origin 冲刷；`AnnouncementWindow` 插话窗口；送达以客户端 `playback.started` 为准；取消期间到达的事件打 `suppressed` |
| [unmute](../04-projects/full-duplex/unmute.md) | 用历史长度当代际，写历史、送 TTS、下发音频三处检查；打断时换掉输出队列，旧协程推不到新队列 |
| [ten-framework](../04-projects/frameworks/ten-framework.md) | TTS 按 `request_id` 丢迟到文本；`tts_flush` / `flush_end` 契约 |
| [pipecat](../04-projects/frameworks/pipecat.md) | 帧级 `interruptible` 标记，打断时一次性清空可打断帧；不按回合 id 过滤（反例） |
| [xiaozhi-esp32](../04-projects/devices/xiaozhi-esp32.md) / [xiaozhi-esp32-server](../04-projects/devices/xiaozhi-esp32-server.md) | 隐式代际：设备 `playback_generation_` 防残余包，服务端每轮 uuid 丢旧音频；异步播报 `notify` 只在 Idle 时接受，忙时直接丢，无 id、无 ack |
