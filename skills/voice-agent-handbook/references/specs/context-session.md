## 1. 解决什么问题

S2S 上游会话随时会丢、会满、会过期，上游实际只保留有限轮数，中途插入的内容模型基本不看。这个组件让三件事成立：1）"上游会话丢了、满了、要换了"是**常规路径**，由唯一的会话重建器从本地上下文重灌；2）模型任何时刻看到的上下文 = 用户实际经历过的对话（听到 / 看到的）+ 我们给的状态，不多不少；3）事实走专门通道，不靠 prompt 和历史记忆碰运气。

适用范围：主要约束 S2S 上游。级联 / 半级联每轮自己拼消息，注入即生效，"只在建会话时带入""中途插入"相关条款对它不适用，数据模型、长会话、错误分级、多连接仍适用。

## 2. 核心模型

### 2.1 术语

| 术语 | 定义 |
|---|---|
| 本地上下文 | 网关 / 编排层维护的对话记录 + 状态块 + 人设 + 工具表。**唯一真相** |
| 上游会话 | S2S 服务端持有的一次会话；同一用户会话下第几个用 `session_seq` 表示 |
| 镜像 | 上游会话里的内容。只写不读，不作重灌来源 |
| 重灌 | 用本地上下文建新上游会话，在建会话参数里带入历史 |
| 用户会话 | `user_session_id`：从开始对话到明确结束或会话恢复窗口过期；可跨多个连接会话（`session_id`）和多个上游会话 |
| 已播放文本 | 用户实际听到（有屏 profile 另含看到）的部分，由上下文层按播放回执换算 |

### 2.2 本地对话记录条目

每条"用户说过、系统出过声或上过屏、调用过工具"的事件都进本地记录；进不进上游、怎么进由投影规则决定，不在记录时决定。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `entry_id` | string | 是 | 本地唯一 id；上行事件带它或可映射到它，条目级错误才能定位 |
| `user_session_id` | string | 是 | 用户会话 id，与 trace 同名字段同值 |
| `session_seq` | int | 是 | 产生该条目时的上游会话代数 |
| `turn_id` | string | 是 | 所属回合；合并的回合取合并后的值 |
| `sentence_id` | int | assistant 必填 | 回合内从 0 递增，与播放回执对齐 |
| `role` | enum | 是 | `user` / `assistant` / `tool_call` / `tool_output` / `system_event`（断线、换会话等，不进上游） |
| `source` | enum | 是 | `model` / `local`（我们合成的"自己的话"：直念的工具结果、事件播报、兜底话）/ `cue`（预合成提示语）/ `user_voice` / `user_ui` |
| `presented_via` | enum | assistant 必填 | `voice` / `screen` / `both`（无屏 profile 恒为 `voice`） |
| `text_generated` | string | 否 | 生成全文，**仅供 trace 与评测** |
| `text_presented` | string | assistant 必填 | 已播放（已上屏）文本：播完 = 全文；被打断 = 按 `played_ms` 截取；没播出 = 空 |
| `text_user` | string | user 必填 | 定稿识别文本；`user_ui` 时为动作的文字化描述 |
| `playback_state` | enum | assistant 必填 | `pending` / `playing` / `completed` / `interrupted` / `skipped`（一帧都没播）；以客户端回执为准 |
| `interrupted` | bool | assistant 必填 | |
| `interrupt_at` | object | 被打断时必填 | `{played_ms, char_offset, estimated: bool}`；文本位置是估算时 `estimated=true` |
| `t_start` / `t_end` | timestamp | 是 | 用户：说话或按键起止；assistant：`playback.started` / `ended\|interrupted` |
| `tool_call_id` | string | tool_* 必填 | `tool_call` 记工具名与参数；`tool_output` 记结果摘要与 `closed_by` |
| `related_entry_ids` | string[] | 否 | assistant 条目关联它所呈现的 `tool_output` |
| `upstream_synced` | enum | 是 | `none` / `live`（已在当前上游会话中）/ `seeded`（由重灌带入） |
| `write_effect` | object | 写操作 tool_call 必填 | `{idempotency_key, executed: bool, result_ref}` |

记录规则：assistant 的 `text_presented` 在播放回执到达后才确定，回执缺失按"未播出"；`source=cue` 只进本地永不进上游；同一回合被切成多段的用户语音合并为一条 `user` 条目；条目只追加不改写，摘要作为独立对象保存。

### 2.3 状态块

系统提示末尾一段结构固定、带版本的短文本，描述"我们自己的数据当前是什么状态"。

| 规则 | 要求 |
|---|---|
| 结构固定 | 字段集合和顺序由 schema 定义（每个 profile 一份）；运行时不增删字段，空值写"无" |
| 版本 | `schema_version`（结构变才升）+ `state_rev`（内容每变 +1），都写进 trace 的 `prompt_version` |
| 只放我们的数据 | 任务 / 流程进度、用户选择、用户告知的硬信息（称呼、同伴等）、当前阶段、"刚说到的点"；**不放**业务事实 |
| 长度 | ≤ 260 字（中文字符），无屏 profile 实践值；有屏 profile 只放与当前阶段相关的字段 |
| 位置 | S2S：系统提示末尾；级联 / 文本 LLM：**消息尾部**，保前缀缓存 |
| 语言 | 自然短句，不写 JSON（避免模型模仿格式说话） |

每个字段在 schema 里声明所属层：

| 层 | 含义 | 生效方式 |
|---|---|---|
| 立即生效 | 不及时更新会让下一轮选错动作（选定的任务、特殊模式、阶段切换） | 两轮之间走注入通道（2.6） |
| 懒生效 | 晚几轮不影响动作（进度计数、次要偏好、"刚说到的点"） | 只更新本地，下次重建或下次立即生效更新时顺带 |

只在两轮之间更新，回合进行中的变化排队；检查点为回合结束、下一回合开始前、文本回合前；更新前等上游空闲。

### 2.4 人设结构

分节清单，拼进系统提示的顺序固定：人设 → 规则 → 状态块。

| 节 | 内容 | 要求 |
|---|---|---|
| 角色 / 背景 / 性格 | 自称、称呼用户、第一人称来历、3–5 个形容词 | 背景不含可被当事实引用的数字、日期、地名 |
| 语域 | 对不同用户群的句长与称呼差异 | 句长可测 |
| 硬规则 | 每轮一两句、数字口语化、先结论后理由、一次只问一个问题、禁 markdown / 列表 / emoji | 必须能写成自动检查 |
| 禁用词 | 去客服味的词表 | 进测试，对照人设、话术模板、提示语三处 |
| 边界 | 事实只说被告知的；超范围统一说法 | 与事实通道配合 |

人设里不写事实、工具说明、路由规则；人设有版本号，只在新建会话时生效。

### 2.5 事实通道的输入格式

| 通道 | 何时用 | 输入格式 | 进本地记录 |
|---|---|---|---|
| 逐字念 | 关键事实：位置、时间、数字、状态结果 | 写好的最终文本（已口语化、数字转读法）+ `fact_ref`（来源 id + 版本）；走本地 TTS 直念 | `assistant, source=local` + `related_entry_ids` |
| 上屏（有屏） | 清单、多选项、待确认字段 | 结构化数据（字段名、值、单位、可选项、`fact_ref`），语音只念要点 | `presented_via=screen\|both`，`text_presented` 记文字化摘要 |
| RAG 注入 | 讲解类 | 分层资料卡（简介 / 正文 / 细节，每次只给当前层）+ "只用资料内信息" + `fact_ref`；分层对象是刚讲过的点 | 注入内容记 `tool_output`，模型回复按 `model` 条目记 |
| 替代方案 | 做不到时 | 随结果下发结构化备选（如 `alternative_times`），不让模型自己编 | 同所属通道 |

关键数字不得只走 RAG（模型会在资料外补细节）。

### 2.6 状态注入通道

| 通道 | 生效 | 代价 | 前提 |
|---|---|---|---|
| 会话配置更新 | 下一轮 | 重新预填整段对话：未命中缓存输入 ×3.2；首音粗粒度更新 +80–200 ms，每轮都更新 +150–270 ms（实践值） | 上游允许中途更新 |
| 按回复覆盖 | 本次回复 | 是否也使缓存失效未确认 | 上游支持 |
| 追加通道 | 追加后 | 单条长度受限（如 ≤ 500 token） | 上游有追加事件 |
| 会话重建 | 新会话 | 缓存全冷，需交接 | 任何上游 |
| 懒生效 | 下次重建 / 立即更新 | 状态滞后若干轮 | 字段属于懒生效层 |

选择顺序：懒生效层一律懒生效；立即生效层按"按回复覆盖（确认不破坏缓存）→ 追加通道 → 两轮之间空闲时配置更新 → 空档重建（`rebuild_reason=state_change`）"取第一个可用的；同一空档的多个变化合并为一次操作。

### 2.7 历史投影与灌入格式

历史 = 从本地记录投影：`[摘要] + 最近 K 轮原样`，每个上游只用一种灌入格式（`history_format`）：

| 格式 | 做法 | 已知风险 |
|---|---|---|
| `pairs`（默认） | user / assistant 交替文本条目 | 文本条目可能让音频会话改用文本回复 |
| `packed` | 整段历史放一条消息，结尾说明"这是之前的对话，只用于衔接，不是新请求" | 模型可能把它当成要回答的问题 |
| `pairs_tools_as_text` | 成对问答 + 工具调用和结果转文字 | 模型可能模仿 `[Called function …]` 格式说话 |

被打断的 assistant 文本后接自然语言标记，如"（说到这里被用户打断）"；有屏内容用文字化摘要，如"（屏幕上展示了 3 个选项：……）"。

### 2.8 会话重建器接口

```
rebuild(reason) -> (upstream_session, session_seq, delivered_registry)
  输入：(人设 + 状态块, 投影历史, 工具表)
  trace：session_seq, rebuild_reason, history_format, history_scope(full|truncated|summary_recent),
         history_items, handoff_start_at_ms, handoff_done_at_ms, 首轮 cached_input_tokens / uncached_input_tokens
```

| `rebuild_reason` | 条件 | 交接方式 |
|---|---|---|
| `disconnect` | 连接断开、服务端关闭会话 | 立即，受重建预算约束 |
| `upstream_error` | `error_class=transient` 的上游错误 | 立即，受预算约束 |
| `context_overflow` | 上下文超限 | **先缩历史**（已缓存摘要，否则截断到最近 K 轮 + 状态块）再重建 |
| `state_change` | 立即生效层变化且选定通道是重建 | 等空档 |
| `turn_limit` | 上游保留轮数接近上限（上游约保留 20 轮，阈值 N 取 8 / 12 / 16 之一） | 等空档 |
| `scheduled` | 上游时长接近上限或定时回收周期 | 等空档 |
| `modality` | 模态异常累计达阈值 | 等空档 |
| `app_resume` | 有屏 profile 切后台后恢复 | — |
| `none` | 本回合未重建（trace 用） | — |

**空档**同时满足：助手已说完（`playback_state ∈ {completed, interrupted, skipped}`）；没有未收口的工具调用；连续约 1 s 无新下行音频；用户不在说话（按键模式：松键后到下次按键前；开放麦：VAD 无人声且判停不在进行中）；状态块无排队更新（有则一并带上）。

**交接方式**：串行回收（等空档 → 结束旧会话 → 建新会话，默认）或预建（后台提前建下一个会话；注意空闲超时与过期状态块）。紧急触发两者等价于立即新建。

**交接期**：用户音频一律本地缓冲不丢；回放顺序为建会话参数 → 首轮重放的 user（若有）→ 缓冲音频；回放可快于实时但守上游限速；交接期只允许本地 cue 和本地 narration 出声。

**断线中断的回合**：最后一个回合无终态时，把最后一条 `user` 作为新会话首轮输入重放，前提是写操作不会重复：未发起写操作 → 重放；`write_effect.executed=true` → 不重放，用本地通道告知结果并写状态块；状态未知 → 先用幂等键查后端，查不到说一句兜底话请用户确认。被打断的 assistant 回复带打断标记进历史，不自动重说。

**"已回传"登记表**：新会话里历史带入的工具结果标 `seeded`，不得再回传；旧会话在途调用由本地收口（`closed_by=superseded`），结果走本地通道；新会话重发旧调用按 `duplicate` 收口不执行。

### 2.9 摘要对象与快照

```yaml
summary: { is_summary: true, covers: [first_entry_id, last_entry_id], text: "…", created_at: … }
snapshot:   # 每个回合终态后写一次，TTL = 会话恢复窗口；不含镜像、不含原始音频
  business_state, state_block: {text, schema_version, state_rev},
  recent_entries: [...],            # 完整条目 schema
  summary, pending_tool_calls, executed_writes: [{idempotency_key, result}],
  session_seq, persona_version, tools_version, form: {…, version}   # form 仅有屏 profile
```

## 3. 规则（不变量）

1. **本地上下文是唯一真相；镜像只写不读。** 为什么：镜像不跟随截断，从它重放会把被打断的回复当成说完了。
2. **历史只在建会话时带入（重灌），不建会话后逐条插入，不用会话 id 接续代替重灌。** 为什么：某项目实测建会话时带入成对问答 6/6，建会话后逐条插入 0/6，会话 id 接续 1/6，中途插入 system / user 条目模型基本不看。
3. **进上游历史的 assistant 文本一律取 `text_presented`，`skipped` 不进历史，被打断的带显式自然语言标记。** 为什么：用生成全文会让模型以为用户听到了没播出的内容；去掉标记只留半句会让模型不知道自己被打断。
4. **"自己的话"（`source=local`）和模型的话同等进历史；`cue` 永不进。** 为什么：模型要知道自己说过什么；提示语走旁路，进模型会污染上下文。
5. **工具调用在本地永远完整保留；进上游时按能力保留或转文字，不得静默丢弃；未收口的调用不进历史，摘要不切断未完成的调用。** 为什么：丢弃工具条目后模型会重复调用或否认已做过的事。
6. **影响后续动作的工具结果和硬信息（名字、同伴、已确认的选择）必须进状态块。** 为什么：早期信息在上游保留轮数之外会丢，摘要会漏；冲突时以状态块为准。
7. **中途插入默认禁止，只允许四种：本会话在途调用的工具结果回传、按回复覆盖（只用于状态块）、追加通道、已回传调用的打断标记。** 为什么：其余中途插入不可靠，且文本条目有让音频会话改用文本回复的风险；不支持按回复覆盖时不得退化为写一条对话项。
8. **每轮 trace 记 `reply_modality`；音频会话出现 `text_only` 即告警，并把文本交本地 TTS 出声，同一上游会话累计 2 次在空档换会话。** 为什么：模态翻转在灌入测试里不一定被发现，线上必须兜底。
9. **全系统只有一个重建器，断线、换会话、错误恢复都走它。** 为什么：多处实现会出现"重连后已回传登记表只有部分路径重建"这类不一致。
10. **非紧急重建必须等空档，不得在助手说话中途切断。** 为什么：中途切会丢音频、重复播报或丢工具结果。
11. **工具表和人设在建会话时一次给全，会话中不改；按阶段限制工具在工具层拒绝并照常收口。** 为什么：多数上游改工具要重连或整段重新预填。
12. **摘要用自己的文本 LLM 提前异步做，输入只用 `text_presented`、`text_user` 和已收口的 `tool_output`，不对摘要再摘要（从原始条目重新生成）。** 为什么：S2S 上游不承担摘要；摘要的摘要会累积失真；用生成全文会把没说的当成说过。
13. **错误四分类，`fatal` 用白名单，未列出的码默认 `transient` 并受重建预算保护；`context_overflow` 不得原样重放；被审核拒绝的回合内容不进后续历史。** 为什么：致命误判会放弃可恢复的会话，原样重放必然再失败，被拒内容带进重建会再次触发。
14. **重建预算按回合计；主动换会话不消耗错误预算。** 为什么：防止一个"毒回合"拖出无限重建。
15. **同一用户会话同一时刻只有一条连接持有前台租约；后台播报用可续期的领取；重连后不重复播已送达的 narration、不重复执行在途写操作。** 为什么：多连接并存时会双声、重复播报或重复写。
16. **所有写工具调用带 `idempotency_key`（与 `turn_id` + 工具名 + 参数绑定），后端按键去重。** 为什么：断线重放的最后一道保险。

## 4. 可调参数

| 参数 | 值 | 性质 |
|---|---|---|
| 状态块长度 | ≤ 260 字 | 实践值（无屏 profile） |
| 上游保留轮数 | 约 20 轮 | 实践值（某上游实测） |
| `turn_limit` 阈值 N | 8 / 12 / 16 之一 | 建议值，需实测 |
| 空档静默 | 约 1 s 无下行音频 | 建议值（开源参考） |
| 等空档上限 | 超阈值后 60 s 仍无空档 → 下一回合结束时强制交接 | 建议值 |
| 交接期音频缓冲上限 | 10 s，超出停缓冲并播一句 cue | 建议值 |
| 摘要触发 | 新增回合数达 `turn_limit` 阈值减 6，或投影历史估算长度达上游上限 70% | 建议值 |
| 最近原样保留轮数 K | 4–6 | 建议值；快照里保留最近 12 轮是实践值 |
| 模态异常换会话阈值 | 同一上游会话累计 2 次 | 建议值 |
| 重建预算 | 每回合 3 次；指数退避首次 ≤ 0.5 s、封顶 10 s；连接稳定 10 s 清零；用尽后按 `fatal` 处理，用户下次主动发起回合重新计数 | 实践值（多框架一致） |
| 重建期间出声 | 无屏 profile 2 s 内必须有本地 cue | 契约 |
| 续接窗口 / 会话恢复窗口 | 30 s / 30 min | 实践值 |
| 播报领取 | TTL 60 s，每 TTL/3 续期；开始回执超时 = 下发完成 + 5 s；重试上限 8 次 | 建议值 |
| 重建后首轮首音增量 | P90 ≤ +300 ms | 建议值 |
| 状态注入首音增量 | < 80 ms | 验收门槛 |

## 5. profile 差异

| 条目 | 无屏设备 | 有屏 App |
|---|---|---|
| 用户会话边界 | 恢复窗口内连续，可很长 | 一任务一会话；任务内上游更替仍走重建器 |
| 主动换会话 | 定时回收 + 轮数阈值 + 状态粗变化，都是常规操作 | 较少；主要由断线 / 切后台 / 轮数触发 |
| 交接空档 | 按键：松键后到下次按键前；开放麦：VAD 静默 + 助手说完 | 开放麦为主；按住说话降级时同左 |
| 状态块形态 | 固定分节短文本 | 表单：屏幕可见可改、有版本；改字段 = 一次 `user_ui` 输入；进模型的是当前阶段字段子集 |
| 已播放文本 | 只有声音，按 `played_ms` 截取 | 声音 + 屏幕，上屏内容以文字化摘要计入 |
| "自己的话"来源 | 多：设备事件、定时器、后台任务的 narration | 少 |
| 事实通道 | 逐字念为主 | 上屏为主，语音念要点 |
| 历史投影 | 最近 K 轮 + 摘要 + 状态块 | 最近几轮 + 表单 + 摘要；级联回合即时拼装 |
| 阶段 | — | 阶段切换属立即生效层；动作集收窄在工具层，不改工具表 |
| 结束产物 | 无 | 结构化产出物（最终表单 + 摘要 + 已呈现文本，带 schema 版本、生成时刻、来源条目范围），确认后幂等写回后端 |
| 重建期间反馈 | 必须有声音 | UI 状态 + 语音填充 |
| 多连接 | 单连接为主，重连时新旧交叠 | 多端 / 切后台，前台租约更常用 |

## 6. 验收清单

有竞态的指标每组 ≥ 20 次，报 P50 / P90。

- [ ] 早期信息召回（第 3 轮说名字，第 25、40 轮追问）：摘要 / 截断方案不低于全量历史。
- [ ] 交接期音频丢失 0；写操作重复执行 0；重连后重复工具调用 / 重发旧工具结果 0。
- [ ] 音频会话中 `reply_modality=text_only` 的轮数 0；首轮把历史当问题回答、模仿格式说话 0。
- [ ] 断线注入（识别中 / 工具执行中 / 已回传未出声 / 出声中）回合终态率 100%。
- [ ] 重建后首轮首音增量 P90 ≤ +300 ms；状态注入首音增量 < 80 ms。
- [ ] `fatal` 类错误触发的重建次数 0。
- [ ] 断线后用户需重说率：重放方案显著低于丢弃方案。
- [ ] 状态块长度、人设硬规则、禁用词自动检查通过。
- [ ] 抽查 trace：进上游历史的 assistant 文本 100% 来自 `text_presented`。
- [ ] trace 覆盖会话与缓存、错误相关字段及 `prompt_version`（人设、工具表、状态块版本）。

## 7. 产出骨架时的注意事项

- 条目 schema 按 2.2 的字段名建类型，`role` / `source` / `playback_state` / `upstream_synced` 用枚举；`text_generated` 和 `text_presented` 分开存，投影函数里只读后者。
- 投影（本地记录 → 上游历史）写成纯函数：输入条目列表、摘要、能力声明（`history.tool_calls`、`history.constraints`、`history.limits`）、灌入格式，输出历史条目；便于单测"skipped 不进、cue 不进、打断带标记、未收口调用不进"。
- 重建器是单例服务，暴露一个 `rebuild(reason)` 入口；空档判定、预算计数、登记表重建、交接期缓冲都在它内部，不要散到连接处理代码里。
- 状态块 schema 每个字段声明 `layer: immediate | lazy`；渲染函数输出固定顺序的自然语言短句，空值写"无"。
- 状态注入通道选择写成按能力声明查表的函数，不按厂商名分支。
- 错误处理只读适配层事件的 `error.class` / `reason`，不在这里解析原始错误码。
- 快照写入挂在回合终态事件上；快照结构不含镜像、不含音频。
- 不要实现"建会话后逐条插入历史"的分支，也不要提供从镜像恢复历史的接口。
- trace 字段名（`session_seq`、`rebuild_reason`、`history_format`、`history_scope`、`history_items`、`reply_modality`、`state_update`）与 trace-evaluation 参考文件一致。
