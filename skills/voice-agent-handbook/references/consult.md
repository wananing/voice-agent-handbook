## 1. 问诊问题

一次把 8 个问题都问出来（可以合并成一条消息），不要一问一答拖十轮。用户已经在描述里回答了的不要再问；答不上来的按"默认假设"往下走，并在方案的"场景与约束回顾"里写明用了哪条默认。

**Q1 设备形态：按键硬件 / 开放麦硬件 / 浏览器 / App？**
- 为什么决定后面：它决定回合边界从哪来。按键和开放麦是同一个回合状态机的两种配置，差别只在边界来源；判停只在开放麦下是真问题。按键设备上所有 VAD 只做辅助（停顿压缩、短按过滤、补充窗口），打断只认按键。
- 答不上来时：有屏 App 或浏览器按开放麦处理；"硬件"但没说有没有按键，按按键处理（更保守，判停和误打断风险都小）。
- 手册：02-architectures/turn-model.md §3、03-mechanisms/turn-detection.md

**Q2 能否在扬声器所在的机器上做 AEC？**
- 为什么：AEC 要用扬声器参考信号，服务端拿不到。做不到端侧 AEC，"说话即打断"不成立，只能按键或半双工。浏览器 `getUserMedia` 的 `echoCancellation`、芯片 AEC（ESP-SR AFE）、移植 APM AEC3 都算端侧。
- 答不上来时：浏览器默认"能"（三项约束全开）；自有硬件默认"不能"，退回按键，并把"评估芯片 AEC 或移植 AEC3"列进下一步。服务端 AEC 不算数（小智服务端 AEC 标 Unstable，每轮冷启动、混网络抖动和 Opus 失真）。
- 手册：03-mechanisms/audio-preprocessing.md、02-architectures/full-duplex.md §4.1

**Q3 用户群：成人 / 儿童 / 户外噪声？**
- 为什么：儿童和噪声放大所有判停方案的失败模式（句中停顿长、声音小、识别错误率高）。服务端 VAD 关不掉的 S2S 和开放麦组装式全双工在这里最先出问题。所有调研仓库都没有儿童语料或评测。
- 答不上来时：按成人室内处理，但在风险里写"如果有儿童用户，判停、降噪、打断方案要重做"。
- 手册：03-mechanisms/turn-detection.md "儿童和停顿多的用户"

**Q4 声音统一、逐字可控、出声前审核有多硬？**
- 为什么：硬要求意味着"文本先于语音"，只有级联和半级联满足。S2S 的文本只比音频早几十毫秒，护栏只能事后纠偏；"自己的话"（工具结果、播报、兜底话）本地合成时和 S2S 原生声音会听成两个人。
- 答不上来时：涉及金额、医疗、订单、地址、儿童内容的，按"硬"处理；纯闲聊陪伴按"软"处理。
- 手册：02-architectures/half-cascade.md §2

**Q5 工具回合占比多大、有没有写操作？**
- 为什么：S2S 普通回合最快、工具回合最慢（实践笔记实测有内容 2.1–2.3 s，同项目级联 1.4 s），慢在"回传后模型再生成一段音频"约 1.2 s。写操作要求后端为真相、幂等键、执行前查代际。
- 答不上来时：按"有工具、有写操作"处理（多数业务 agent 最终都会有），写操作约束进方案。
- 手册：02-architectures/s2s.md §3、03-mechanisms/tool-calls.md

**Q6 能否依赖闭源上游的会话语义？**
- 为什么：S2S 的判停、上下文注入、轮数上限、缓存、错误语义都由上游决定，换上游可能要重写适配。实践笔记里建会话后逐条插入历史 0/6 被使用、会话 id 接续 1/6、`session.update` 让未命中缓存的输入 ×3.2。
- 答不上来时：按"能，但不想被锁死"处理：上游差异写成能力声明字段（LiveKit `RealtimeCapabilities` 的做法），通用代码不按厂商名分支。
- 手册：02-architectures/s2s.md §4

**Q7 中文要求？**
- 为什么：unmute、moshi 的模型只训练了英语（法语），换语言要换模型；其余框架语言中立，中文能力取决于所接的 ASR / TTS / 实时模型。框架层面跟中文相关的只有分句标点、判停阈值这类细节（按空格切词的实现对中文会把整段回复憋到流结束）。
- 答不上来时：用户用中文提问就按"要中文"处理。
- 手册：05-comparison/framework-matrix.md 第五节

**Q8 自托管还是云？**
- 为什么：开源 S2S 权重（Qwen3-Omni、Step-Audio 2）没有流式输入和实时服务端，自托管时只能当半级联理解端；自托管 TTS 的流式、取消、许可差异很大（只有 CosyVoice CV2/3 支持文本流入；六个开源 TTS 都没有显式取消接口）。
- 答不上来时：按"云优先、关键组件可替换"处理；有数据合规要求时按自托管。
- 手册：05-comparison/model-matrix.md 第二、三节

## 2. 决策树

先定链路（说什么、谁决定），再定双工方式（说话时听不听）。双工是独立一维：组装式全双工可以建在级联、半级联或 S2S 之上。

- 需要附和、重叠、抢话，且只做英文演示、不要工具？
  - 是 → **[A] 原生全双工**（研究 / 演示，不进产品）
  - 否 → 要求出声前有完整文本？（审核、逐字念、声音统一、工具密集、写操作，任一为硬要求）
    - 是 → 需要专门挑 ASR（中文、方言、儿童），或需要用户转写进历史？
      - 是 → **[B] 级联**
      - 否，想省 ASR 一跳或用模型的音频理解 → **[C] 半级联**（自托管理解端 24 GB 到 80 GB 级卡）
    - 否（在场感优先、工具少、能依赖闭源上游）→ 工具回合占比高？
      - 是 → 回到 [B] / [C]，或按回合混合（寒暄走 S2S，事实和工具走级联 / 半级联；混合的四个前提见 half-cascade §5.2）
      - 否 → **[D] 半双工 S2S**（云端实时 API）
- 然后定双工方式（对 B / C / D 都适用）：有可靠端侧 AEC 且成人为主？
  - 是 → 开放麦 + 可打断（组装式全双工）
  - 否（无 AEC、儿童、户外噪声）→ 按键半双工

### 2.1 叶子的推荐组合

**[A] 原生全双工**
- 框架：moshi
- 判停：模型内部，唯一旋钮 `pad_mult`
- 打断：没有打断事件，由模型决定
- 首音：结构性解决（自述约 200 ms）
- 工具回合：无
- 评测：只有性能基准；体验靠人工听

**[B] 级联**
- 框架：livekit-agents、pipecat；中文硬件可从 xiaozhi-esp32-server 起步（要补协议，见否决条件）
- 判停：开放麦 VAD 0.2–0.3 s + 音频语义判停 + min/max 0.5 / 3.0 s；按键只认按键
- 打断：代际冲刷；按 TTS 播放时刻截断，写已播部分 + 打断标记
- 首音：首段短切 → 真流式 TTS → 预热与并行建连 → 开放麦才开抢先生成（只抢 LLM，遇工具撤销）
- 工具回合：可模板化的本地直念 + 不再生成；要组织语言的回传再生成 + 短 cue
- 评测：分段计时，有声音 / 有内容分开报

**[C] 半级联**
- 框架：livekit-agents（`RealtimeModel(modalities=["text"])` + TTS）、pipecat（`realtime-openai-text.py` 示例）；自托管理解端 Step-Audio 2 mini / Qwen3-Omni（只用 Thinker）/ Ultravox
- 判停：完全自控；开源理解端无流式输入，开放麦先判停再整段提交
- 打断：同级联，按 TTS 播放位置截断
- 首音：照搬级联的分句、流式 TTS、预热、cue，不做抢先生成
- 工具回合：工具调用先于声音，结果可直接念
- 评测：理解端和"ASR + 同底座 LLM"在同一批样本上比
- 额外要解决：理解端不产出用户转写，说话期间并行跑流式 ASR 最稳

**[D] 半双工 S2S**
- 框架：livekit-agents `RealtimeModel`、pipecat S2S 服务；要前台 / 后台分工时参考 qwen-audio-agent
- 判停：能关服务端判停就关、自己判停后 commit；关不掉用上游语义判停 + 上游前停顿压缩
- 打断：上游 `speech_started` 只负责发现；cancel、truncate（按设备回执）、代际自己做
- 首音：普通回合不花工程；工具回合在 function call 到达时本地播预合成 cue（不进上下文）
- 工具回合：先探上游有无静默收口；没有就回传再生成 + cue，或改走 [C]
- 评测：冻结盲测集；按版本比较人设、状态块；长会话召回脚本

### 2.2 不随链路变的三个结构决策

不管走哪个叶子，都对下面三项给一个"必须做 / 可以从简"的结论：

| 结构决策 | 必须认真做 | 可以从简 |
|---|---|---|
| 回合模型：`turn_id` 贯穿每帧、每回合恰好一个终态、识别回显软确认 | 无屏硬件；多来源出声；要过滤迟到帧、按回合统计 | 单一链路、有屏幕、原型 |
| 话筒归属：单话筒、代际、租约、插话窗口 | 多个出声来源；回合外有播报；S2S 上游可能推迟到帧 | 纯级联、只有模型回复一个来源 |
| 状态与上下文：后端为真相、本地上下文为真相、状态块、快照 | S2S；断线频繁的设备；有写操作；长会话 | 纯级联、短会话、无写操作 |

## 3. 场景配方

用户场景能对上其中一个时，直接以配方为底稿，再按问诊结果改。

### 3.1 按键儿童硬件（中文，无屏）

| 项 | 选择 |
|---|---|
| 链路 | 级联；半级联（Step-Audio 2 mini 整段提交正好对应松键）作备选，前提是理解端在儿童语音上不低于"ASR + LLM"（需实测） |
| 框架 | xiaozhi-esp32 `manual` 模式 + xiaozhi-esp32-server 起步，补 `turn_id`、终态、播放回执 |
| 模型 | FunASR 2pass 流式中文 ASR；带 TN 的流式 TTS（CosyVoice）；文本 LLM 任选 |
| 判停 | 只认按键；VAD 只做停顿压缩、短按过滤（< 250 ms 或语音 < 150 ms）、补充窗口（smart-turn P < τ 时留 600 ms，上限 1 s）；不用文本判停 |
| 打断 | 只认按键：设备本地立即停播、清缓冲、本地代际 +1，再上报播放位置和 `abort` |
| 首音 | 识别定稿即起跑；首段 ≥ 6 字遇标点切、12–15 字强制切；本地预合成 cue 第一优先级；每个 `failed` 都要发声 |
| 工具 | 状态、进度类本地直念 + 不再生成；写操作后端判定、幂等键、执行前查代际；递归上限 3–5 步 |
| 评测 | 主锚点松键（T_rel）；儿童真人录音冻结集为准，模拟用户只找回归；在自己的样本上定 VAD 和 smart-turn 阈值 |

已知坑：小智协议没有 turn id、没有播放回执，被打断的回复全文写入历史；点击打断可能残留约 1.2 s 已缓冲音频；CosyVoice 无取消接口，要自加停止标志；RNNoise 无增益下限，不要压儿童主路；AGC2 在户外底噪下恰好不放大小声孩子；所有判停参数都没在儿童集上测过。

### 3.2 浏览器客服（工具密集、有写操作）

| 项 | 选择 |
|---|---|
| 链路 | 级联或半级联。客服评测纯 S2S 44%、S2S + 外围工程 62%、纯文本大模型 68%（qwen-audio-agent 自述，文本口径） |
| 框架 | livekit-agents（发言级仲裁、异步工具、`say()`）或 pipecat（`run_llm=False`、`pipecat eval`）；要节点式流程用并入 pipecat 本体的 Flows（1.5.0 起） |
| 模型 | 云或自托管均可，每段单独评测；最强文本 LLM 做决策 |
| 判停 | 开放麦：VAD 0.2–0.3 s + 音频语义判停 + min/max 0.5 / 3.0 s，有条件开动态端点 |
| 打断 | 浏览器三项约束全开；服务端 VAD 起说 + AEC 预热 3 s + 最短 0.5 s；判停和打断都在服务端 |
| 首音 | 抢先生成只抢 LLM，遇工具撤销；首段短切；TTS 建连与 LLM 并行 |
| 工具 | 可模板化结果本地直念；需组织语言时回传再生成，工具 > 300 ms 先播 cue；秒级写操作走异步（先回"已提交"收口，结果等插话窗口）；写操作门槛留在委派之前，同一回合只认第一个写调用 |
| 评测 | 每次提交 L0 冻结盲测集（含 ASR 噪声变体和写操作负例）；发布前 L1 脚本，竞态脚本多次重复按通过率；主锚点判停（T_ep） |

已知坑：pipecat 打断只清队列、不按代际过滤迟到帧；livekit-agents 服务端镜像没处理 `truncated`；短工具委派后台反而更慢（1.317 s → 3.363 s）；框架自带评测默认是文本模态，不等于测过语音链路。

### 3.3 自有开放麦硬件（音箱、免按键）

| 项 | 选择 |
|---|---|
| 链路 | 组装式全双工建在级联上（unmute 的路线，硬件版是小智 `realtime` 模式） |
| 框架 | 服务端 livekit-agents / pipecat；设备侧参考 xiaozhi-esp32 的状态机门控和 `playback_generation_` |
| 模型 | 同级联；ASR 前加判别支路降噪，主路默认不降噪 |
| 判停 | 同 3.2；静音时长按采样数算，VAD 不设绝对音量门槛 |
| 打断 | 必须端侧 AEC：芯片 AEC 或移植 APM AEC3（播放期间麦克风常开、实例跨轮保持、render 取 DAC 前最后一份 PCM）；服务端 VAD 起说 + 过滤；做不到就退回按键 |
| 首音 | 同级联；无屏设备预合成 cue 优先 |
| 工具 | 同 3.2；有事件播报时加插话窗口，以设备播放回执为准 |
| 评测 | 边播边说录音测 AEC 收敛时间和残余回声；误打断率进 trace |

已知坑：ESP-SR AFE 只对白名单板型开放；小智服务端 AEC 标 Unstable；小智 `realtime` 下（设备端 AEC）服务端要等 ASR 出整句才打断；附和和咳嗽不过滤就会被自己的听众打断。

### 3.4 纯自托管中文

| 项 | 选择 |
|---|---|
| 链路 | 级联为主；半级联用 Step-Audio 2 mini（7B、原生工具解析、权重 Apache 2.0） |
| 框架 | pipecat 或 livekit-agents；判停模型用 smart-turn（8 MB、CPU、BSD、可微调），LiveKit v1-mini 闭源只作对照 |
| 模型 | ASR：FunASR 2pass，端侧 sherpa-onnx；TTS：CosyVoice（六个开源 TTS 里唯一支持文本流入）或 VoxCPM（代码和权重 Apache-2.0、停止迭代即停） |
| 判停 | 按设备形态走 3.1 或 3.2 |
| 打断 | 代际冲刷；TTS "能否中途停止"当硬指标 |
| 首音 | 自己切分，不用 TTS 内置切句；在自己的并发下实测首块（裁首部静音），目标 P50 ≤ 0.4 s（需实测） |
| 工具 | 级联同 3.2；Step-Audio 2 不自动续答，天然可跳过再生成 |
| 评测 | 同一归一化口径的 CER、TTS 回转 CER、首包 P50 / P90；单机并发自己压测 |

已知坑：端到端模型都不产出用户转写，要另跑 ASR；Step-Audio 2 要用 stepfun 的 vLLM 分支；Qwen3-Omni 只用 Thinker 也要约 69–79 GB；fish-speech 商用需另签、index-tts 大主体需申请；多数模型权重许可要单独核对；unmute 按空格切词对中文无效。

### 3.5 快速原型验证

| 项 | 选择 |
|---|---|
| 链路 | 云端 S2S（一个 API）或最简级联 |
| 框架 | openai-realtime-agents（浏览器直连，chat-supervisor / handoff 两种参照）；或 pipecat / livekit-agents 的示例 |
| 模型 | 云服务；级联时用 ASR 自带端点（FunASR 800 ms、sherpa 1.2 s） |
| 判停 | 服务端 VAD 或纯 VAD 静音：够用，但别在上面调体验 |
| 打断 | 框架默认；可以只做"取消任务 + 清队列 + 回合级 id 过滤" |
| 首音 | 不优化，但两个首音分开打点 |
| 工具 | 框架默认 |
| 评测 | 冒烟；只算均值、5 次左右的测试只能当冒烟 |

已知坑：openai-realtime-agents 是参考配置不是运行时（没有测试、没有重连、工具在浏览器执行、没有跳过再生成）；原型上 S2S 普通回合的速度不能外推到工具回合。

### 3.6 最低延迟的成人闲聊

| 项 | 选择 |
|---|---|
| 链路 | 半双工 S2S（普通回合首音 0.87–0.96 s 量级）；英文研究演示可看 moshi |
| 框架 | livekit-agents `RealtimeModel`（`RealtimeCapabilities` 能力位）或 pipecat S2S 服务 |
| 模型 | 云端实时模型，按能力位而不是厂商名选 |
| 判停 | 上游判停（能关就关、自己判）；浏览器端开三项约束 |
| 打断 | 上游 `speech_started` 发现；`cancel` + `truncate(audio_end_ms)` 以回执为准；不支持 truncate 的上游（Gemini / AWS）只改本地 |
| 首音 | 普通回合不花工程；工具回合本地 cue 不进上下文 |
| 工具 | 少工具；工具表建会话时一次给全，按阶段在工具层拒绝 |
| 评测 | 冻结盲测集；长会话召回脚本（名字、早期信息） |

已知坑：历史只能在建会话参数里带入（中途插入 0/6）；上游约 20 轮上限要靠状态块 + 主动换会话；`session.update` 让缓存失效（输入 ×3.2）；本地 cue 和原生声音听成"两个人"；往音频会话灌文本可能翻转成纯文本回复。

## 4. 否决条件

方案写完后逐条过一遍。命中任一条就换掉或在风险里写明为什么仍然选。

### 4.1 链路

| 链路 | 不要选，如果 |
|---|---|
| 级联 | 闲聊陪伴、普通回合首音和自然度要求极高；需要副语言理解且不愿另接分类器；资源紧张、不想运维三套模型 |
| 半级联 | 强调语气和在场感；普通回合首音要压到 S2S 的 0.9 s 量级；不想自托管大模型（开源理解端要么推理弱，要么要 80 GB 卡） |
| 半双工 S2S | 工具密集；事实必须准确、要出声前审核；长会话强记忆；按键、儿童、户外噪声且上游服务端 VAD 关不掉 |
| 原生全双工 | 需要工具、事实、审核、中文、长会话（约 5 分钟上限）、并发的任何产品；按键说话设备 |
| 组装式全双工（开放麦） | 没有可靠端侧 AEC；高噪声、儿童 |

### 4.2 框架与项目

| 项目 | 不要选，如果 |
|---|---|
| pipecat | 多出声来源、上游可能推迟到帧，又不打算自己补代际过滤；要求 OpenAI Realtime 截断精确到播放位置（按墙钟、未扣缓冲） |
| pipecat-flows | 用独立包（已冻结于 1.4.0）；跑在 S2S 上（Flows 依赖的帧在 OpenAI Realtime / Gemini Live 上未实现或无动作） |
| livekit-agents | 单会话开销敏感（一会话一进程）；上游是 Gemini / AWS / Ultravox 又要自己判停（关不掉）；依赖 GPT-Live 做静默收口；Krisp 降噪插件是商业授权 |
| ten-framework | 要装在终端用户设备上或与 Agora 竞争（许可附加条款）；需要异步工具、上下文截断、带退避的重连 |
| openai-realtime-agents | 当生产运行时用；需要异步工具或跳过再生成 |
| qwen-audio-agent | 需要级联或本地判停（仓库无本地 VAD）；需要按播放位置截断 |
| unmute | 中文；需要工具或长会话（每轮全量历史、无摘要） |
| moshi | 同原生全双工 |
| xiaozhi-esp32-server | 不补协议直接上产品：没有 turn id、没有播放回执、被打断全文写历史、断线不恢复、无异步工具 |

## 6. 需实测的决策点

手册对下面 13 个点没有数据，只有推算或建议值，而它们会直接改变选型。用户场景命中哪个，就把对应实验写进方案第 5、6 节。

1. **S2S 上游的服务端 VAD 能否关闭**（DashScope `turn_detection: null`、Doubao mute / unmute 能否当"按键期间才听"）。影响：按键设备能否用 S2S。实验：对目标上游跑探针，建会话时关服务端判停，按键期间故意停顿 1–2 s，看上游是否切段、是否在松键前自行回复或调工具；各 20 次。关不掉就按 turn-detection"按键 + 服务端判停关不掉"的停顿压缩方案兜底，或换链路。
2. **上游收到工具结果后有无静默收口选项**，以及跳过再生成后 S2S 的有内容首音（估算约 1.1 s）。影响：工具密集产品选 S2S 还是半级联。实验：回传 `function_call_output` 后不发 `response.create`，看上游会不会自己开口；有静默选项时测"本地直念 + 不再生成"的有内容首音 P50 / P90。
3. **上游 cancel 后是否真会推来迟到音频 delta**。影响：S2S 下是否必须做中心仲裁和每帧代际比较。实验：在回复中途发 cancel，记录之后 0–2 s 内收到的同 response 的 delta 数，重复 20 次以上。只要出现过，就必须每帧比代际。
4. **开源理解端（Step-Audio 2、Qwen3-Omni、Ultravox）的 TTFT 和端到端首音**。影响：自托管半级联能否达到松键到首音 P50 ≤ 1.1 s。实验：在目标卡型上用真实长度的语音（3–8 s）测预填充 + 首 token，加上自选 TTS 首包，报 P50 / P90。
5. **理解端在儿童语音、户外噪声下是否不低于"ASR + 同底座 LLM"**。影响：儿童硬件选级联还是半级联。实验：同一批儿童真人录音，两条链路跑同一套 L0 用例，比动作命中和槽位命中。
6. **smart-turn、LiveKit turn detector 的中文和儿童准确率**，以及判停参数在儿童集上的表现。影响：开放麦中文能否依赖语义判停；儿童配方的参数。实验：建自己的儿童 / 停顿样本集（标注"说完 / 未说完"），扫 VAD PR 曲线、画 P(完成) 分布再定阈值 τ 和补充窗口。
7. **自托管中文 TTS 单并发首块 P50 ≤ 0.4 s 是否可达**（IndexTTS、VoxCPM 没有首包数字）。影响：自托管级联的首音预算。实验：在自己的卡和目标并发下测"发请求到首块"，裁掉首部静音再计时，分并发 1 / 2 / 4。
8. **抢先生成在中文、按键场景下的命中率和浪费率**。影响：开放麦中文场景值不值得实现。实验：开抢先生成跑一周 trace，统计命中率（目标 ≥ 70% 才保留）和被丢弃调用占比（先按 ≤ 30% 监控）。
9. **级联"全串行 3.6 s → 优化后 1.1–1.4 s"只是推算**。影响：级联能否满足闲聊场景的首音。实验：在同一条链路上逐项打开分句、流式 TTS、并行建连、抢先生成，每步测有内容 P50 / P90。
10. **框架、模型的单机并发路数**。影响：成本和部署形态。实验：用自己的链路和卡型压测，以首音 P90 不超预算为约束找最大并发；手册里没有任何一页给出可比数字。
11. **ASR / TTS / 端到端模型权重许可、框架代码许可**。影响：能否商用。实验不是技术实验：逐个查权重托管页（ModelScope / HF）的许可，TEN 的附加条款、fish-speech、index-tts 单独确认。
12. **降噪方案在目标人群录音上的识别率、误切段率**。影响：主路是否降噪。实验：分"只进判别支路"和"也进主路"两组 A/B，看识别率、误切段率和首音变化；户外场景加风噪、防风罩、高通截止频率三个变量。
13. **除 OpenAI Realtime 协议外，框架是否支持 S2S 与级联按回合切换；云端文本模态计费**。影响：混合架构是否可行、半级联云成本。实验：查目标框架能否按回复选模态；对目标上游用文本模态跑一批回合，核对账单。
